Code signing policy

The Windows installer is not code signed yet. Windows SmartScreen shows a full-screen panel whose only visible button is “Don’t run”; continuing means clicking “More info”, then “Run anyway”. SmartScreen is a reputation system rather than a malware verdict, and it fires on files it has not seen often, including signed ones.

Rather than asking you to trust that, check it. Every release carries a SHA-256, and every installer is built by a public GitHub Actions workflow that records where it came from: 

gh attestation verify Hearth-Setup-0.1.0.exe -R EricFinland/hearth-windows

Release artifacts are built only on GitHub-hosted runners, never on a maintainer’s machine, and every signing request will be approved by a person. Eric Catalano is Author, Reviewer and Approver; multi-factor authentication is required on the repository and the signing account. The installer registers a standard Windows uninstall entry.

Hearth does not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. Model downloads and update checks are the only destinations, both user-initiated, and every one is listed.

Free code signing will be provided by SignPath.io, certificate by the SignPath Foundation. Full policy: docs/code-signing-policy.md.

Before you trust it with anything

A local model is weaker than a hosted one. The workspace boundary stops writes outside the folder you choose, but not reads and not network traffic. Approving a command by reading its text is not a security control. The limitations page says what each protection misses, and is the one worth reading first.
